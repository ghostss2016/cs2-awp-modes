
## Единый источник исходников — указание владельца 25.09.2026

- Единственная основа исходников плагинов, панели и сборщика — соответствующие репозитории GitHub и их отслеживаемые ветки. Обычное обновление и обновление после смены движка используют одинаковые источники, заданные общим манифестом, с фиксацией точных коммитов.
- На .100 допустимы рабочие копии этих коммитов, кэш и результаты сборки; отдельная локальная версия плагина не является источником релиза.
- Все необходимые доработки сначала проверить, закоммитить и отправить в отслеживаемую ветку GitHub. Перед выпуском проверить наличие коммита на GitHub. Не выпускать код из незакоммиченных изменений или только локальных коммитов.
- Автоматически вычисленные данные движка хранить в общем signatures.ini с доказательствами проверки и привязкой к версии/хешам движка. Генерация данных не разрешает скрытые изменения кода плагина вне GitHub.
- Владелец разрешил автоматическую перекомпиляцию при обновлении движка: основание — изменение проверенной версии движка, даже если коммит плагина прежний. Учитывать в идентичности сборки коммит и движок; повтор того же задания не создаёт новую версию.
- Доставка игровых файлов только через существующие карточки и общую очередь панели.
- Перед удалением лишних копий/локальных веток на .100 сначала перенести необходимые изменения в GitHub и проверить их сохранность. Ветки GitHub этим запросом удалять не разрешено. Активные checkout, кэш, доказательства проверки и используемые сборки не считать мусором без проверки зависимостей.

Эти правила источников и доставки заменяют прежние инструкции ниже о локальной папке как основе, sync-from-disk и прямой раскатке. Технические сведения ниже сохраняются для справки.

## Сборка и доставка

Правки фиксируются в отслеживаемой ветке GitHub. Сборку запускает панель через центральный fleet-build.yml. Результат поступает в локальный каталог панели, затем в карточку и общую очередь. Прямые выгрузки из рабочих папок не использовать.

## Две проверки перед раскаткой

```bash
# 1. не тянет ли слишком новый GLIBC (на серверах Steam Runtime, glibc 2.31)
objdump -T ИМЯ.so | grep -oE 'GLIBC_2\.[0-9]+' | sort -u | tail -3     # 2.33+ — нельзя

# 2. символ должен быть ОПРЕДЕЛЁН в плагине (B), а не импортирован (U)
nm -D ИМЯ.so | grep g_bUpdateStringTokenDatabase
```

## Раскатка на сервера

⛔ **Не перезаписывать `.so` поверх работающего сервера.** Файл замаплен в память
процесса; перезапись «на месте» (в том числе через файловый API панели) роняет сервер
с SIGBUS в ту же секунду и выкидывает всех игроков — 13.08.2026 так уронили несколько
серверов подряд.

Безопасно: положить файл рядом и **атомарно переименовать** (`mv`) — так делает
`cs2-ci/ci/deploy-node.sh` — либо остановить сервер штатно через панель. Новый `.so`
подхватывается только при запуске процесса; сервера перезапускаются ночью в 3:00.

## Правила, общие для всего флота

- Конфиги, `.vdf` и данные в `addons/data/` — **собственность сервера**, не раскатывать
  их пачкой: они настроены под каждый сервер отдельно. Деплой = только `.so`.
- Перед массовой раскаткой сверять контрольную сумму записанного файла, перечитав его
  с сервера: тихий сбой записи иначе выглядит как успех.
